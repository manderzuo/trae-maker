# 星链维度分流系统独立化设计

**日期：** 2026-09-21  
**状态：** 待规格审阅  
**范围：** 将当前 AI Work 内置 CORE 管理能力拆分为独立的“星链维度分流系统”，并将 AI Work 收敛为执行端。

## 1. 目标与边界

本次改造建立两个清晰边界：

```text
客户端 / Agent
    ↓ 用户自己的 CORE API Key
星链维度分流系统（独立 API + 管理界面）
    ↓ 内部管理员中转 Key
AI Work 助手（执行端）
    ↓
文字、视频、素材执行
```

星链维度分流系统是用户身份、用户 API Key、额度、并发、队列、任务归属和消费账本的唯一权威。AI Work 助手负责已有的上游账号、真实积分读取、模型执行和结果获取，但不再创建或维护普通用户 API Key。

本次不接入在线支付，不公开底层账号池，不把 Cookie、JWT、底层账号标识或单账号积分发送给 CORE 或客户端，也不改变现有 AI Work 的上游凭据保存方式。

## 2. 产品形态与命名

新增独立 Windows 程序，显示名称为：

> 星链维度分流系统

程序具有两个同进程能力：

1. 可配置监听地址和端口的 HTTP API 服务；
2. 独立的管理界面，用于执行端连接、用户、Key、额度、任务和系统状态管理。

建议二进制文件名为 `starlink-dimension-router.exe`，默认监听端口与 AI Work 的 7864 分离，使用可配置默认值 7865。实际地址、端口、数据目录和跨域策略均从配置读取，不写死公网域名。

AI Work 助手继续保留原有桌面程序，但在“桥接执行端”模式下只生成、轮换和展示管理员中转 Key。普通用户 Key 创建、撤销、权限、额度和用量界面从 AI Work 的普通 API 管理路径移除或改为只读迁移提示。

## 3. 身份与 Key 边界

### 3.1 AI Work 管理员中转 Key

AI Work 只允许存在一个当前有效的桥接管理员 Key，支持轮换。历史 Key 可以在迁移期间保留为禁用记录，但不能继续访问执行入口。Key 具备内部执行所需的能力，例如模型读取、文字执行、视频提交、素材访问和桥接汇总读取；具体 scope 采用白名单配置。

Key 明文只在创建或轮换成功时显示一次，由管理员复制到星链维度分流系统。AI Work 本地只保存安全摘要或受保护凭据引用；日志不得写入 Key、Authorization 头或带凭据的 URL。

星链维度分流系统保存该 Key 时使用系统安全存储或加密配置，不在普通用户查询、任务日志和管理列表中显示明文。

### 3.2 CORE 普通用户 Key

普通用户 Key 只能由星链维度分流系统创建。每个 Key 绑定一个 Core 用户，拥有：

- 可调用能力和模型范围；
- 永久额度和用户级额度约束；
- 文字、视频、素材的并发和速率限制；
- 启用、撤销和有效期状态；
- 可审计的创建、充值、消费和退款流水。

用户 Key 不进入 AI Work 的 `api_keys.json`，也不被转发到 AI Work。CORE 转发到 AI Work 时始终使用桥接管理员 Key，并通过内部关联 ID 关联原始用户、Key、请求和任务。

### 3.3 管理员身份

星链维度分流系统保留独立的 Core 管理员身份，用于管理用户、普通 Key、额度、任务和执行端连接。AI Work 桥接管理员 Key 不是 Core 管理员 Key，不能直接用于修改 CORE 用户或额度。

## 4. 数据流与结算

1. 客户端向星链维度分流系统提交请求。
2. CORE 从 Authorization 中解析普通用户 Key，得到权威用户身份；不信任客户端传入的用户 ID、转发头或请求体身份字段。
3. CORE 解析模型和能力，先检查用户、Key、模型、并发、速率、排队和永久额度。
4. CORE 生成内部 request ID、任务 ID 和幂等作用域，预占用户额度并持久化任务。
5. CORE 使用桥接管理员 Key 调用 AI Work 的执行 API，同时传递不可伪造的内部关联信息；不把普通用户 Key 传给 AI Work。
6. AI Work 使用现有账号池和上游执行能力完成文字、视频、素材任务，并返回上游任务状态或结果。
7. CORE 根据可核验的执行结果结算用户账本；未知费用进入待对账，不自动换号、不自动重放、不虚构退款。
8. 用户只能读取自己名下的额度、任务、素材和结果；管理员才能读取聚合管理数据。

用户业务额度和 AI Work 上游真实积分分别记录，不做未经确认的 1:1 换算。CORE 的“当前积分”和“今日消耗”默认指 CORE 用户账本；若能从 AI Work 获取可信的上游聚合余额，则以独立卡片显示“执行端上游汇总积分”，不得与用户额度合并。

## 5. 独立 API 契约

### 5.1 用户兼容 API

星链维度分流系统对外提供与当前兼容矩阵一致的入口：

- `GET /v1/models`
- `POST /v1/chat/completions`
- `POST /v1/videos/generations`
- `GET /v1/videos/{id}`
- `GET /v1/videos/{id}/content`
- `POST /v1/assets`
- `GET /v1/assets/{id}/content`

其中 `model=seedance` 的 Chat 请求由 CORE 按视频任务解析，仍返回明确的异步状态；文字模型走文字执行路径。参考图先在 CORE 归属用户后，再以内部素材 ID 交给 AI Work。

### 5.2 管理 API

管理 API 只在管理员认证后可用，路径统一使用 `/admin/v1`：

- `GET /admin/v1/status`：CORE 运行状态、版本和监听信息，不含凭据；
- `GET /admin/v1/summary`：活跃普通 Key 数、CORE 额度聚合、今日消费、预占和任务计数；
- `GET /admin/v1/bridge`：桥接配置的脱敏状态；
- `POST /admin/v1/bridge/test`：使用已保存或本次提交的桥接 Key 测试 AI Work；
- `POST /admin/v1/bridge/sync`：拉取并保存模型能力和允许展示的执行端聚合数据；
- `GET/POST /admin/v1/users`：用户管理；
- `GET/POST /admin/v1/keys`：普通 Key 创建和列表；
- `POST /admin/v1/keys/{id}/revoke`：撤销普通 Key；
- `GET/POST /admin/v1/quotas`：用户和 Key 额度查询、充值和审计流水；
- `GET /admin/v1/jobs`：脱敏任务、状态、费用状态和对账状态。

管理响应只返回必要字段和聚合值。禁止返回 AI Work 的账号池、底层 UID、Cookie、JWT、账号名称、单账号积分、内部文件路径和上游授权 URL。

### 5.3 AI Work 桥接 API

AI Work 新增仅供星链维度分流系统使用的桥接能力：

- `GET /internal/bridge/status`：验证桥接 Key 和返回执行端版本、可用能力；
- `GET /internal/bridge/models`：返回可公开给 CORE 的模型目录；
- `GET /internal/bridge/summary`：只返回执行端聚合运行信息和上游聚合积分，不返回账号池明细；
- 现有 `/v1/*` 执行入口：要求桥接管理员 Key，并识别内部 request ID、幂等键和任务关联信息。

桥接接口不能由普通用户 Key 调用。AI Work 的桥接模式拒绝没有桥接身份的公网业务请求，避免用户绕过 CORE 直接调用执行端。

## 6. 管理界面

星链维度分流系统使用独立界面，首屏不再显示 AI Work 旧的调度配置弹窗。布局包括：

### 顶部状态区

- 系统名称：星链维度分流系统；
- CORE 服务状态、数据库状态、执行端连接状态；
- 最近同步时间、最近错误和刷新按钮。

### 汇总卡片

- 活跃 API Key 数量；
- CORE 当前可用积分；
- CORE 预占积分；
- 今日已结算消耗；
- 运行中/排队任务数；
- AI Work 执行端上游汇总积分（单独标注来源和更新时间）。

### 执行端连接

- AI Work Base URL；
- AI Work 管理员中转 Key；
- 测试连接；
- 拉取模型和汇总数据；
- 连接成功、失败、过期和数据更新时间。

### 用户与 API Key

- 新建用户；
- 新建普通 API Key；
- scope、模型能力、并发和速率设置；
- Key 只显示前缀，明文只在签发成功时显示一次；
- 启用、禁用和撤销操作要求二次确认。

### 额度与流水

- 用户和 Key 的总额度、可用、预占、已结算；
- 管理员充值和人工调整；
- 今日消费和历史流水；
- 失败、未知和待对账状态单独显示；
- 不使用 token 估算积分，不按日自动恢复永久额度。

### 任务与对账

- 用户、模型、能力、状态、费用状态、创建时间和更新时间；
- unknown/reconcile_required 任务禁止重放；
- 不显示上游账号池和底层账号身份。

## 7. 迁移与兼容

迁移分为只读检查、映射预览、人工确认、应用和核验五步：

1. 读取当前 AI Work/Core 数据，生成用户、Key、额度、任务和素材的摘要及源文件哈希；
2. 将现有 Core 用户、普通 Key、用户额度和可恢复任务迁移到星链维度分流系统数据目录；
3. 生成一个 AI Work 桥接管理员 Key 并在 CORE 中建立桥接配置；
4. 完成 `/internal/bridge/status`、模型和聚合数据测试；
5. 切换 CORE 对外入口，保留旧数据备份和只读迁移报告；
6. 核验用户 Key、额度、任务归属、幂等记录和结果下载；
7. 只有在核验通过后，才将 AI Work 切换为桥接专用模式。

旧 AI Work API 服务可以在迁移阶段保持 `off` 或兼容模式，但切换到桥接专用模式后，不允许旧普通 Key 继续绕过 CORE 调用执行能力。迁移失败不得自动删除旧 JSON、SQLite、素材和视频结果。

## 8. 安全与失败策略

- 管理 API、桥接 API 和用户 API 使用不同认证层；
- CORE 不信任客户端 `user_id`、`x-user-id` 或代理添加的身份头；
- bridge test 失败时不保存未验证的 Key，不显示伪造的积分数据；
- bridge sync 部分失败时保留上一次可信快照，并显示过期时间；
- AI Work 离线时 CORE 返回明确的执行端不可用，不删除用户预占；
- AI Work 返回未知提交结果时任务进入待对账，禁止换号重试；
- 普通 Key、管理员 Key 和中转 Key 均不写入日志；
- 所有管理写操作记录操作者、对象、原因、前后差异和时间；
- 默认监听本机地址，公网暴露需通过已配置的 HTTPS/Nginx/FRP 链路；
- 测试和验收使用 Mock/Fake 执行端，不发送真实上游生成请求。

## 9. 验收标准

必须验证：

1. AI Work 界面只能创建或轮换桥接管理员 Key，不能创建普通用户 Key；
2. CORE 可以配置桥接 URL/Key，测试成功后能拉取模型和允许展示的聚合数据；
3. CORE 界面显示活跃 Key 数、CORE 可用/预占/已结算额度、今日消耗和任务计数；
4. CORE 界面不显示账号池、UID、Cookie、JWT、单账号积分或上游授权信息；
5. CORE 创建的普通 Key 可以调用文字和 Seedance 视频接口，额度、scope、并发和幂等规则生效；
6. 普通 Key 不能直接调用 AI Work 的桥接接口；
7. AI Work 只接受有效桥接身份进行外部执行；
8. 用户不能访问其他用户的任务、素材、额度和流水；
9. bridge sync 失败保留旧快照并标注过期，不伪造当前积分；
10. 迁移可重复执行且不会重复签发、重复扣费或删除旧数据；
11. 前端自动化测试、Rust 单元/集成测试、API 契约测试和构建全部通过；
12. 生产验收不调用真实上游生成，临时构建和测试输出优先放在 `D:\gpt`。

## 10. 明确不在本次范围内

- 在线支付、充值订单和第三方财务系统；
- 将 AI Work 上游账号凭据迁移到 CORE；
- 向 CORE 或客户端暴露账号池、单账号积分和底层登录状态；
- 自动根据提示词推测用户额度或上游真实积分；
- 为了兼容旧客户端而长期保留普通 Key 绕过 CORE 的执行入口；
- 自动清理旧数据、旧任务结果或迁移源文件。
