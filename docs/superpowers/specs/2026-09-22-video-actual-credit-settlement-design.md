# 公网视频真实积分结算设计

## 目标与范围

公网 Core 的普通 Key 视频请求必须按可核验的单任务上游积分费用结算，不再把任务受理当作完成，也不再固定扣 1。未取得费用证据时不得宣称已实际扣费。管理员授予的 Key 总额度、已使用、持有中和剩余额度须保持一致，且同一视频任务只能结算一次。

本轮覆盖 `POST /v1/videos/generations` 和 `/v1/chat/completions` 中选择 `seedance` 的视频路径，以及视频任务查询、Core 账本和 AI Work 桥接回执。普通文字模型当前同样固定扣 1；这是独立的已知问题，本轮不把它宣称为真实上游积分，也不改变文字服务放行。Core 用户额度仍由管理员授予，不从 AI Work 聚合余额自动充值。

## 已核实的问题与约束

- Core 当前对视频预占 1，并在 AI Work 返回 202 和任务 ID 后立即 `Commit(1)`；任务完成或失败不会更新这笔账。
- AI Work 当前视频任务保存状态、资源和时长，但没有可信的单任务积分费用字段。账号池汇总余额可能同时受其他任务影响，不能用前后差额归因到某个 Key。
- Core 的现有 `credits` 账本使用整数；上游余额显示小数。即使以后取得费用回执，也需要明确定义精度和迁移边界。
- 公网 Core 当前运行且没有视频暂停开关。发布修复前，现有错误计费仍可能发生；不得声称已暂停。
- 既有“周”Key 的明文不能从 Core 哈希反推出；不得读出或打印秘密，不因测试私自轮换该 Key。

## 方案选择

采用“任务级回执 + 无证据不结算 + 视频默认暂停”。固定视频单价无法表示真实消耗；聚合余额差不能在共享账号和并发调用下证明单任务费用，均不作为用户账本依据。若一次受控真实测试仍不能获得可信的任务级积分回执，普通公网视频保持暂停，不用估值或管理手工猜数恢复。

### 暂停与一次性验收

新增持久化的视频计费闸门，默认 `paused`。它同时拦截直接视频提交和 `seedance` Chat 兼容提交，发生在 Core 预占与 AI Work 转发之前；模型发现、既有任务查询和下载不受影响。返回明确的可机器识别错误，管理界面显示暂停原因与待对账数。配置和状态在重启后保持，不依赖临时环境变量。

真实验收只允许管理员预先登记一个现有普通 Key 的内部 ID、精确请求哈希和一次性验收标识，原子消费后不可重放；其它用户仍被闸门拒绝。首选“周”Key，不新建或轮换 Key。仅一条最小规格、非素材的视频，真实费用仍会消耗 AI Work 上游积分。没有该 Key 的合法明文或用户侧代发能力时不绕过鉴权；请用户在自己的客户端发起已约定请求。测试过程不记录明文 Key、Cookie、JWT、提示词或完整原始 SSE。一次性豁免不得变成可长期使用的视频旁路。

### 费用回执与任务关联

AI Work 视频适配层只从该任务的上游响应或上游提供的任务/用量查询中提取费用证据，并与本地任务 ID、上游请求引用、计费单位、来源和观测时间绑定。诊断阶段仅记录脱敏的候选费用字段名、单位、数值和任务关联证据；未验证字段含义前不向 Core 提供 `actual_credits`。企业 API 中以人民币表示的成本、Token 使用量、视频时长和账号余额变化均不能直接当作个人积分费用。

可信回执必须证明：费用属于这一任务，单位是上游积分，数值非负且精度受支持；重复读取同一来源返回同一值。没有这些条件时回执标记 `unverified` 并附安全错误码，不包含上游账号或鉴权信息。Core 独立校验回执，不能因桥接 HTTP 200 就信任任意 JSON 数字。

### 预占、结算和精度

任务受理只创建持有中额度和任务关联，不写成功/实际消耗。明确未被上游接受的请求释放持有；明确已接受但费用未知、连接中断或结果不确定的任务进入待对账，既不释放也不固定提交。任务完成且回执可信时，在一个事务中按实际费用结算、释放多余持有、更新任务与请求状态。重复轮询、并发回调或重启恢复不得重复入账。若实际费用大于预占、与已结算值冲突或证据失效，禁止越额提交并转待对账，通知管理员。

普通视频重新开放必须同时满足两项：可核验的单任务积分回执，以及由已验证上游规则给出的请求最大费用上界，以便在调用前预占且不超支。不能证明上界时只允许已授权的一次性诊断测试，不开放普通视频。验收测试本身的费用未知时保持持有和待对账，不伪造账单。

只有费用回执和最大费用上界都证实可用时，才进行精度迁移并恢复普通视频。精度采用版本化定点积分账本，按 `10^6` 微积分储存、接口显示十进制积分。现有整数 `credits` 授予、持有与结算在事务迁移时乘以 `10^6`，逐项检查溢出；失败回滚，不部分发布。所有读取和写入 `credits` 的路由同步转换单位，普通文字请求当前固定 1 的逻辑行为保持为 1 个显示积分，不得误变成百万积分或百万分之一积分。超过六位小数的上游费用不四舍五入入账，而进入待对账。`video_job` 等其他逻辑资源不混入积分。迁移前备份只放在 `D:\gpt`，不删除旧数据库或用户数据。

### 历史错账与界面

已固定扣 1 的历史视频请求标记为“旧版未核验结算”，不能把它们当作真实上游费用。只有取得对应任务的可信费用证据后，才以追加式更正账目补差或退差；否则保留原账和待核验标记，由管理员看见并处理，不静默改写历史条目。Key 列表和概览分别显示总额度、已核验消耗、旧版未核验、持有中和可用余额；AI Work 聚合积分仍单独展示且不能混加。

## 验证与发布

先用本地模拟上游做测试：两个入口都暂停、无预占拒绝；受理但未完成只持有；成功精确结算；明确失败释放；未知结果待对账；重复/并发/重启不双扣；费用越界不透支；小数精度与迁移回滚；历史账目只追加更正。若真实回执或费用上界不存在，只验收暂停、诊断和待对账路径，不执行精度迁移或声称精确结算已上线。测试缓存与产物放 `D:\gpt`，测试后只清理本轮明确产生的临时文件。

发布分阶段：先部署暂停闸门并核查公网确实拒绝新视频且文字/既有下载不受影响；再部署只读费用诊断；最后用一次经管理员限额和“周”Key 鉴权的公网最小视频验证单任务费用。用户已授权这一项真实付费测试，不扩展到多次或并发压力测试。若无法取得可信回执或最大费用上界，维持暂停并报告缺口；只有模拟测试、迁移核对和真实回执验收全部通过，才由管理员显式恢复普通视频。

## 非目标

不以 Token、固定单价、视频时长或聚合余额差代替真实积分；不自动发送第二次真实请求；不改变账号池、上游凭据和其他用户数据；不把文字服务的固定 1 积分错误掩饰成已经修复。
