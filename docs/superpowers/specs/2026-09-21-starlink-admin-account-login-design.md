# 星链维度分流系统管理员账户登录设计

**日期：** 2026-09-21  
**状态：** 待规格审阅  
**范围：** 用管理员账户登录会话替代 Core 管理界面中的管理员 API Key 输入。

## 1. 目标与边界

Core 管理界面改为账户登录模式：管理员访问 `/admin` 后先登录账户，浏览器使用安全会话 Cookie 调用 `/admin/v1/*` 管理接口。页面不再要求用户粘贴、保存或了解 Core 管理员 API Key。

本次不改变：

- 普通用户 API Key 的创建、作用域、积分和并发限制；
- AI Work 与 Core 之间的内部桥接凭证；
- 面向外部客户端的 `/v1/*` API 认证方式；
- Core 数据账本和用户权限模型。

默认管理员账户为 `admin`，初始密码使用用户指定的值。密码只在初始化时用于生成不可逆密码哈希，数据库不保存明文；首次登录后要求修改初始密码。

## 2. 认证架构

```text
浏览器 /admin
    ↓ POST /admin/v1/login
Core 校验账户密码
    ↓ HttpOnly + SameSite 会话 Cookie
管理员管理 API /admin/v1/*
```

### 2.1 账户存储

在 Core 数据库中新增管理员账户认证表，保存：

- `user_id`：关联现有 Core 管理员用户；
- `password_hash`：PBKDF2-HMAC-SHA256 哈希及随机 salt；
- `password_iterations`：哈希参数；
- `must_change_password`：是否仍使用初始化密码；
- `updated_at`：凭证更新时间。

不得把初始密码写入仓库、日志、HTTP 响应或普通配置导出。

### 2.2 会话

- 登录成功后创建高熵随机会话令牌；服务端只保存令牌哈希、管理员 ID、创建时间、过期时间和 CSRF 值；
- 浏览器 Cookie 使用 `HttpOnly`、`SameSite=Strict`，公网 HTTPS 下设置 `Secure`；
- 默认会话有效期 12 小时；退出登录立即撤销当前会话；
- 服务重启后会话失效，避免持久化会话泄露；
- 管理 API 统一从会话获取管理员身份，再复用现有 `Principal` 与管理员授权逻辑。

### 2.3 登录防护

- 登录失败按来源地址和账户组合限流；
- 错误响应不区分“账户不存在”和“密码错误”；
- 所有管理写操作检查同源请求/CSRF 防护；
- 管理 API 不把会话令牌写入日志或错误消息；
- 旧的 Bearer 管理员 Key 认证暂时保留为兼容通道，但不在新管理页面展示或生成，后续可单独撤销。

## 3. HTTP 接口

新增公开但不泄露管理数据的登录接口：

- `GET /admin/v1/session`：返回当前是否已登录、管理员名称、是否必须修改密码；
- `POST /admin/v1/login`：接收账户和密码，成功后设置会话 Cookie；
- `POST /admin/v1/logout`：撤销当前会话并清除 Cookie；
- `POST /admin/v1/password`：已登录管理员修改密码并清除旧会话。

现有 `/admin/v1/summary`、用户、Key、额度、桥接和迁移接口全部改为接受会话认证；未登录返回统一 `401 admin_login_required`。

首次初始化接口只在数据库尚无管理员账户时可用，创建 `admin` 账户并初始化密码；已有管理员账户时不可重复初始化。

## 4. 管理界面

### 未登录状态

页面只显示登录卡片：账户、密码、登录按钮和错误提示。不显示 Core 管理员 API Key 输入框、Key 保存复选框、Key 清除按钮或初始化后返回的明文 Key。

### 已登录状态

保留现有管理功能：

- 运行与额度概览及自动刷新；
- AI Work 桥接配置；
- 用户与普通 API Key；
- 中文作用域勾选和最大并发数；
- 积分配置；
- 退出登录和修改密码入口。

若 `must_change_password=true`，先显示修改密码界面，成功后才能继续使用管理功能。

## 5. 迁移与兼容

1. 数据库升级增加认证表，不删除现有 Core 用户、额度、任务或 API Key。
2. 已有 `admin` 用户首次登录时，如果没有账户密码记录，使用本次初始化流程写入哈希。
3. 旧 Core 管理员 Key 不在 UI 中显示，也不尝试反解；兼容 Bearer 入口暂时保留，便于内部过渡。
4. 管理界面不再使用浏览器 localStorage 保存管理员凭证。
5. 初始化密码只能在首次初始化请求和本机初始化环境中使用，响应只返回登录成功状态，不返回任何管理员 Key。

## 6. 测试与验收

必须覆盖：

- 正确账户密码登录成功并设置 Cookie；
- 错误密码返回统一 401，不能枚举账户；
- 未登录访问管理接口返回 401；
- 登录会话可访问现有管理接口并保留管理员授权；
- 退出后旧 Cookie 失效；
- 修改密码后旧密码失效、新密码生效；
- 首次登录强制改密；
- 会话 Cookie 属性符合 HttpOnly、SameSite 和 HTTPS 部署要求；
- 管理页面不再包含 Core 管理员 Key 输入、localStorage 保存逻辑或明文 Key 文案；
- 现有 Core 全量测试、并发限制测试和 UI 契约测试继续通过。

## 7. 安全上线要求

公网部署前必须使用 HTTPS 反向代理，禁止直接把 Core 7865 端口暴露到公网。管理员账户应在首次登录后立即修改初始密码，公网入口还应配置请求体限制、登录限流和必要的 IP 访问控制。
