# Core 专用账号的容量核对

本功能将“每个 Key 的实际扣费结算”和“上游账号可再次授权的容量”分开：回执确认后先进入持久 outbox；账号整体容量随后在空闲窗口核对。原始费用记录始终保留。

## 启用前提

管理员明确保证名单中的上游账号只经 Core 使用，不在官方客户端、其他代理或脚本中消费。这是运维约束，不是上游提供了最终账单标记。先用只读及受控实测验证真实积分包响应，再启用生产配置。

在 AI Work **数据根目录**（与桥接数据库同层，而不是其 `data` 子目录）放置：

```json
{"version":1,"accounts":["实际确认专用的账号UID"]}
```

文件名为 `bridge-dedicated-accounts.json`。没有文件或名单为空时不开启；不支持通配符。最多256个不同账号，文件最多32KiB。该文件不是凭据，不填写 API Key/JWT，也不能从公网请求提交。移除某个账号即停止后续自动容量核对，Schema9新包准入也在每次准备/consume/send时立即拒绝，旧费用和占用不会被删除。

初次新建容量记录时，积分包基线与容量在同一事务写入。旧版会话必须全部已有可信Final回执、无冲突，且回执观测与更新时间不晚于容量读取；历史存在本身不阻止新基线，也不修改/重新扣除旧账。对于已有容量但没有基线，或存在未知费用的账号，不自动认定历史已对清；需要先完成专门迁移核验。不要删库、清占用或用当前余额覆盖历史事实。

## 核对条件

1. 账号没有准备中、执行中、待回执或冲突费用；执行已终态且单请求回执符合既定唯一会话的完成后读取政策。
2. 在持久账号栅栏期间读取权益包；网络不持数据库或全局 runtime 锁。
3. 旧包仍可匹配，限额/生效期未变化，用量没有下降；新增包的已有用量也计入增量。
4. 全部包用量增量，精确到百万分之一积分，等于本地尚未覆盖的实际扣费合计。
5. 提交时实例、栅栏、快照、账单事件和旧会话水位未变化。

新容量、覆盖事实、新基线同事务提交；失败全部回滚。缺失的旧包只有已过期且已完全用尽时可以接受；有效或未用尽包缺失、退款、未知积分产品、重复包、上游字段不稳定或不一致的实际扣费，都不能凭猜测覆盖。该情况下仍保留财务事实，并需要进一步核验；不是永久保证任意历史余额都能自动恢复。

当前支持通用积分产品208、每月登录积分221、Work积分产品209。真实只读响应已确认稳定身份字段为 `entitlement_base_info.entitlement_id`；优先使用其摘要，其次支持显式 `id`，均不落库原始账号信息；缺少身份字段时要求完整非 `usage` 内容保持稳定，变化时保守拒绝。

真实响应中签到积分包可能为 `usage: {}`。仅已知产品208/209/221、有效稳定ID、完整起止期限、`status=1`及`ent_status=0`组成明确原生UNUSED契约时，才按已使用0解析；缺条件的稀疏空对象保持排除，`usage:null`或格式损坏仍拒绝。显示用改写副本不能用作金融证据。

## Schema9 独立新包容量

旧P/R仍阻断整账号静止重基线。为了不把独立新本金也阻断，Schema9记录未包含在旧anchor中的新UNUSED包不可变本金；只接受原生字符串`entitlement_id`，拒绝旧数值ID别名重复计入。本金、元数据、首次证据不可变，当前确认与查询开始水位单独保存，不删除或重写旧快照、占用、D与回执。

确认最多有效60秒；准备、reserve、consume和send-intent均核对专用授权、有效期限、当前包存在及已知用量。较新缺包/失败/未知观测使旧确认失效，同毫秒歧义保守关闭，旧响应晚到不能恢复失效确认。所有权威原生读取使用原始响应；栅栏内重基线第二读开始前撤销额外确认，成功新anchor吸收该包后不再叠加本金。成功读取的显示余额独立于租约/栅栏状态更新。

保留原D扣减、P/R保护和实时余额预检；额外本金不能当作最终费用或退款。紧急启动开关`--disable-new-package-capacity`关闭新增容量计算，须继续使用Schema9兼容版本和当前账本，不可恢复Schema8账本覆盖新费用。实际迁移、历史21笔保留与三条公网收费验收见[视频迁移验收](video-migration-repair-20261012.md)。

首次包级核对曾对一个真实账号做过连续两次只读查询：支持真实包结构，零变化匹配；该历史检查本身不是实际付费覆盖证明。2026-10-12后续三例视频的实际生成与结算证据单独保存在上述迁移验收记录。

## 运行与边界

- 已完成回执但尚未核对容量的账号仍进入现有后台刷新队列；重启可重新发现。复用4个worker及已有退避，不创建每请求新线程，不再次生成视频。
- 已启用账号的原生显示余额在API启动及每60秒由最多4个只读worker更新；专用账号使用原始响应确认新包，显示副本不作为财务覆盖证据。准备新请求发现容量增长时仍可触发一次栅栏内重读，只有无P/R、无未终态执行/冲突且精确差额匹配时才原子重基线。存在占用时保留旧快照，Schema9独立新包可按上述严格条件授权，原请求和费用事实保留。
- 桥接权益查询15秒总超时。单 Key 账单/额度释放不等待账号整体容量核对；但被核对账号短时不接新预算，其他账号仍可工作。
- 此功能不提供跨账号分摊，不把池外消费计入某个 Key，不放行未知价格，也不冻结整个 Key 余额。
- schema7首次新增独立基线表，当前Schema9再新增包见证与读取水位；各阶段原子迁移。旧程序不能直接打开不支持的Schema。生产升级前须做一致性备份和副本迁移验证；有新交易后不能覆盖回旧备份来“回滚”。

隔离测试使用合成权益包及真实本地事务，并非上游官方账单、真实下载或公网验收证据。
