# 视频响应流读取与未知任务恢复修复（2026-10-12）

## 问题与处理

旧视频消费循环使用 `reader.lines().flatten()`，会忽略读取错误。若响应解码器持续返回错误，循环无法收尾；连接只返回心跳时也缺少整体等待期限。原始读取错误未被保存，因此不能从旧任务反推上游最终结果或实际扣费。

视频生成现在只读到第一次错误；生成 POST 的整体 deadline 为 780 秒，覆盖响应体阻塞读取，心跳不能续期。消费器另行检查总期限并限制单个事件为 1 MiB，包括没有换行和多行数据。损坏 JSON、超长事件、未见最终信号就结束都保存闭合 `video_stream` 诊断与 unknown 状态，不能当作成功、零费用或退款。

诊断绑定原预算发送身份并加密持久化，不改变原 task/session/request/budget。已有独占锁恢复流程继续保留 P/R/D。维护扫描仅处理旧 generation 且有 durable send_intent 的非终态视频；保留已有诊断，修复落后的任务 DTO，以 64 条游标分页持续前进。当前 generation、未发送预算与已确认终态不受此分类影响。

Core 的原 GET 视频状态接口对这种任务返回 `task.status=unknown`，并提供结果与费用待核对的安全说明；真实 ready 结果优先，支持迟到结果。Studio 已有 unknown 契约与查询中断处理，无需改动网页或手机布局。没有新增付费重发路径。
