# 资源池、跨账号会话与远程网关开发计划

> 目标：让 AI Work Assistant 同时管理 Trae 通用积分与 Work 积分，可靠完成账号池自动切换，在外置 API 和 Trae Work CN 客户端中保持工作上下文，并安全地把办公室网关提供给局域网及家庭网络使用。

## 1. 范围与边界

本计划包含五条主线：

1. 通用积分、Work 积分和总积分的完整展示及资源感知调度；
2. 非流式和流式请求的自动换号、冷却、余额热更新；
3. 外置 API 的跨账号有状态会话；
4. Trae Work CN 的一键/自动切号、项目恢复与对话接力；
5. 本机、局域网、腾讯云中转三种网关访问模式。

明确边界：

- 不把账号 A 的 Trae 云端会话 ID 伪装成账号 B 的会话。服务端按 UID 校验归属，直接复制会形成不可继续的“幽灵会话”。
- Trae Work CN 跨账号采用“新会话 + 上下文接力”，保留工作语义，但不承诺保留原云端会话 ID。
- 私钥、JWT、refresh token、Cookie 不进入代码仓库、日志或导出文件。SSH 私钥只通过本机配置引用路径。
- 先保持现有 `127.0.0.1` 默认值和无状态 API 兼容性，新能力均以显式配置启用。

## 2. 当前基线

- 积分缓存已经分别保存 `general`、`work` 和合计 `credits`；资源调度页与运行时池按资源类型取号（文字通用、Seedance Work）。
- 前端每 30 秒刷新积分缓存，运行中的 API 池会热更新成功刷新的账号余额。
- 网关已有账号池、冷却、五种池内策略和最多三账号轮换；非流式换号较完整，流式 SSE 收到业务额度错误后不能保证在同一请求内换号。
- OpenAI/Anthropic/Responses 请求支持显式 `conversation_id` 与 `X-Conversation-ID`，本机 SQLite 可选持久化并导出 Markdown/JSON；默认无 ID 的旧客户端仍无状态。
- Trae Work CN 已有登录态快照、项目导航键级合并、一键切号与额度信号自动切号；切换失败会尝试恢复源账号，云端原会话 ID 不跨 UID 伪装。
- API 网关支持 `listen_host`、LAN API Key 强制、可选 CORS 白名单；腾讯云路径使用显式 SSH 反向隧道、StrictHostKeyChecking 与可选断线重连。

## 3. 总体架构

```text
客户端（本机 / 局域网 / 家中）
        │ OpenAI / Anthropic API + conversation_id
        ▼
安全入口（本机直连 / LAN / 腾讯云 HTTPS）
        ▼
AI Work Assistant 网关
  ├─ API Key、限流、审计
  ├─ 会话库与上下文裁剪
  ├─ 资源路由（文字 / 视频 / 图片）
  ├─ 账号池（通用 / Work / 总额 / 冷却）
  └─ Trae Work 客户端接力编排
        ▼
Trae / Seedance / 未来图片服务
```

## 4. 开发阶段

### 阶段 A：双积分展示与余额热更新（1～1.5 天）

任务：

- 资源调度账号行同时展示总积分、通用积分、Work 积分。
- “全部账号余额”和全局资源摘要改为三项统计。
- 账号池候选不再仅按 `general_credits > 0` 过滤；先展示全部有任一余额的账号。
- `PoolEntry` 增加 `general_credits`、`work_credits`、`total_credits`，保留旧 `credits` 数据迁移兼容。
- 引入资源额度策略：`general`、`work`、`combined`、未来 `video` / `image` 独立口径。
- 30 秒刷新完成后热更新运行时池，不要求重启 API 服务。
- 在真正启用 `combined` 文字调度前，用单账号小请求验证上游扣减顺序；没有实证时保持资源类型隔离，防止错误放行 Work-only 账号。

验收：

- 仅通用、仅 Work、两者都有、两者都为零四类账号展示正确。
- 缓存刷新后 3 秒内 `/status` 的池余额与页面一致。
- 余额为零的账号不会被对应资源选中；另一类积分不被误判。

### 阶段 B：完整自动换号（1.5～2 天）

任务：

- 新增 `sequential_drain` 策略，实现固定 A → B → C 顺序耗尽。
- 最大换号次数改为 `min(池内健康账号数, 可配置上限)`，默认不再固定为 3。
- 修复流式请求：首个有效内容尚未下发时发生额度/认证错误，可安全切换账号并重试同一请求。
- 已经向客户端发送内容后禁止自动重放，避免重复回答或重复工具调用；返回明确的可恢复错误，下一轮自动使用新账号。
- 区分永久额度耗尽、临时频控和套餐限制；额度耗尽进入长期保护，30 秒余额刷新发现恢复后自动解冻。
- 账号成员、分组与余额支持热应用，减少“保存后需重启网关”。
- 增加调度日志：请求 ID、资源类型、账号掩码、切换原因、重试次数；不记录凭证和完整正文。

验收：

- A 额度耗尽后，非流式请求在同一请求内切 B 成功。
- 流式请求在首字前耗尽时切 B 成功；首字后失败不重复生成。
- 10 个账号池可跨越前三个故障账号继续找到健康账号。
- 并发请求不会集中击穿同一余额接近零的账号。

### 阶段 C：外置 API 跨账号会话（2～3 天）

任务：

- 保持默认无状态模式，兼容现有 OpenAI/Anthropic 客户端。
- 新增可选 `conversation_id`：接受请求体字段及 `X-Conversation-ID` 请求头。
- 使用本地 SQLite 保存规范化消息、模型、资源池、创建/更新时间和摘要；敏感正文支持本机加密。
- 请求只携带最新消息时，由网关补齐历史；客户端已携带完整历史时做去重。
- 超过上下文预算时采用“最近消息 + 滚动摘要”，保留工具调用配对关系。
- 账号切换只改变上游凭证，不改变本地会话键。
- 增加会话列表、导出、删除、保留天数和“关闭正文持久化”选项。

实现状态：会话列表、Markdown/JSON 导出、单会话删除、保留天数清理和正文持久化开关已接入 API 配置页；云端 Trae SOLO 会话端点仍不固化，避免伪造跨 UID 云端会话。

验收：

- 同一 `conversation_id` 连续对话期间从 A 切 B，模型能引用 A 阶段的信息。
- 重启助手后会话可恢复。
- 不传 `conversation_id` 的旧客户端行为完全不变。
- 删除会话后数据库正文和索引均清除。

### 阶段 D：Trae Work CN 一键切号与对话接力（3～5 天）

先做一键模式，再开放自动模式。

任务：

- 实现 F-68：切号前保留 `local-project-folders`、`recentlyOpenedPathsList`，恢复后只合并这两个全局键；账号分区键不跨 UID 合并。
- 增加“切换并继续工作”按钮：等待当前生成结束 → 保存当前登录态 → 切换目标账号 → 重开原项目。
- 从代理观测或余额刷新检测额度耗尽；设置余额阈值和“仅提示 / 一键切换 / 自动切换”三级模式。
- 建立对话接力包：项目路径、用户目标、最近若干轮对话、未完成事项、关键文件和工具结果摘要。
- 切到新账号后创建新会话并注入接力包；保留原账号会话只读存档链接。
- 自动模式必须有生成中锁、进程关闭超时、快照完整性校验和失败回滚。

实现状态：自动模式已有网关 inflight 锁、切换事件去抖、源快照保存、项目导航状态合并和失败后源账号回滚；“上下文注入”保留为本机会话存档/接力包，不向目标 UID 伪造原生云端会话。

验收：

- A 用完额度后，一键切 B 能重新打开同一项目并继续任务。
- 自动模式不会在模型正在输出或工具执行中强制关闭客户端。
- A/B 各自的账号分区会话数据不被互相覆盖。
- 切换失败时恢复原登录态和原项目，不留下半写快照。

### 阶段 E：局域网模式（0.5～1 天）

任务：

- 网关设置增加 `listen_host`：默认 `127.0.0.1`，可选 LAN `0.0.0.0` 或指定网卡地址。
- LAN 模式强制至少存在一个启用的 API Key，禁止匿名访问。
- 增加允许来源/CORS 白名单，仅在浏览器客户端需要时启用。
- 页面显示本机局域网访问地址，并提供 Windows 防火墙规则引导。
- `/health` 保持最小信息；状态和模型接口继续鉴权。

验收：

- 同一局域网设备携带 API Key 可访问；无 Key 返回 401。
- 非白名单浏览器来源被拒绝。
- 切回本机模式后局域网端口不再监听。

### 阶段 F：腾讯云安全中转（1～2 天）

推荐路径：办公室电脑主动建立 SSH 反向隧道，腾讯云只在本机回环端口接收隧道，再由 Nginx/Caddy 提供 HTTPS。

```text
AI Work 127.0.0.1:7864
  → SSH -R 127.0.0.1:17864:127.0.0.1:7864
  → 腾讯云 127.0.0.1:17864
  → Nginx/Caddy :443 + TLS + 限流
  → 家中客户端
```

任务：

- 助手设置增加 SSH 主机、端口、用户、私钥路径、远端回环端口和域名；私钥只存路径，不复制内容。
- 使用 Windows OpenSSH 启动 `ssh -N -T -R`，启用 `ServerAliveInterval`、`ServerAliveCountMax`、`ExitOnForwardFailure`。
- 隧道由助手托管：启动、停止、断线指数重连、状态显示和脱敏日志。
- 首次连接必须人工核对服务器 host key 指纹，禁止静默使用不安全的 host-key 策略。

实现状态：接口配置页已提供 SSH 端口、远端/本地端口、可选 SHA256 主机指纹与断线自动重连；OpenSSH 强制 `StrictHostKeyChecking=yes`，未被 known_hosts/指纹确认的主机不会启动。
- 腾讯云配置 Nginx/Caddy TLS、请求体大小、SSE 禁用缓冲、长连接超时、频率限制。
- 云端安全组只开放 SSH 与 HTTPS；反向隧道端口只绑定腾讯云 `127.0.0.1`。
- 家中客户端继续使用 AI Work API Key；可选叠加 IP 白名单或 WireGuard。

部署前还需要：腾讯云公网 IP/主机名、SSH 用户名、SSH 端口、服务器系统、域名与 DNS 控制权。SSH 私钥由用户指定的本机文件提供，但不得提交仓库。

验收：

- 办公室网络无公网 IP 时，家中仍可通过 HTTPS 调用。
- 隧道断开后自动重连，重连期间请求明确失败，不绕过鉴权。
- 腾讯云上无法直接访问反向隧道端口，只能经 HTTPS 入口访问。
- 重启办公室电脑后可按用户配置自动恢复隧道。

### 阶段 G：安全、回归与交付（1 天）

- Rust 全量单测、前端测试、流式/非流式集成测试。
- 账号池并发、余额临界值、隧道断线、应用重启和快照回滚测试。
- 日志与仓库敏感信息扫描，确认无 PEM/JWT/Cookie/API Key。
- 更新用户手册、故障排查和回滚说明。
- 每一阶段独立提交，提供配置迁移和关闭新能力的回退开关。

## 6. 推荐实施顺序

1. 先完成 A、B，解决积分口径和自动换号的基础正确性。
2. 再完成 C，让外置 API 的跨账号切换真正无感。
3. D 先交付“一键切换并接力”，稳定后再开放自动切换。
4. E、F 在核心网关稳定后实施；远程部署期间保持本地监听，不直接暴露办公室端口。
5. 每阶段验收通过后再进入下一阶段，不把积分、会话、客户端自动化和公网暴露一次性上线。

## 7. 开发决策点

## 7.1 验收策略（用户确认）

- 改造阶段以代码实现、接口衔接、配置迁移和静态完整性为主，不提前进行会消耗真实积分或改变账号登录态的业务验证。
- 阶段 A～F 的功能全部完成后，再统一进入阶段 G，按“积分与调度 → API 会话 → Trae 切号接力 → Seedance 视频 → 图片服务 → 局域网 → 腾讯云远程”的顺序逐项验收。
- 统一验收前，模拟测试只允许使用本地伪造响应或不访问上游的演练入口；不得用真实生成任务替代最终验收。
- 若某一项验收失败，记录失败日志和回滚点，修复后从该项重新开始，不跳过后续项目。

实施前需要确认或通过小规模实测决定：

1. `llm_utils_chat` 在当前账号/项目下是否会自动从 Work 积分扣费，以及通用/Work 的优先顺序。
2. 顺序耗尽策略是否固定按用户拖拽顺序，还是支持主池/备用池两级。
3. 外置 API 会话正文默认是否持久化；建议默认关闭、用户显式开启。
4. Trae Work 自动切号阈值；建议先用“剩余积分低于一次预估消耗”而不是严格等于零。
5. 腾讯云入口使用已有域名还是新建子域名；没有域名时先用 VPN/SSH 隧道测试，不以裸 HTTP 正式开放。

### 阶段 E/F：局域网与腾讯云安全中转实现记录
