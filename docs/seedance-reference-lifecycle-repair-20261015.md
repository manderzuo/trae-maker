# Seedance 直连客户端参考素材生命周期修复

S015 在新任务提交时复用了已经过期的临时图片素材 ID。Core 在辅助模型执行前返回 `reference_asset_expired`，客户端却只保留 HTTP 400 的异常摘要。画布中的原文件存在，并不能保证之前上传取得的临时网关 ID 仍然有效。

## 修复行为

- CLI 与 MCP 共同使用的 PowerShell runner 在每条独立新任务提交前，从明确选择的原文件上传新的参考素材。历史上传 ID 通过当前网关和凭据作用域内的来源记录定位原文件，校验 SHA256、媒体类型和大小后重新上传；不盲目延长旧 ID。
- 所有来源先检查，再执行首次上传；文件缺失、变化、类型不符、没有当前账号来源记录时，在付费 POST 前停止。不会扫描目录猜测替代文件。当前图片上限为 9。
- 保持原参数协议的顺序：每种媒体先按 asset ID 数组的给定顺序，再按本地路径数组的给定顺序。需要精确混排尾帧和角色图时，传完整的有序 `image_paths` 数组。
- 每个提交键在上传前以 create-new 方式持久认领。相同成功键返回原任务回执，不重新上传或提交；并发重复、输入变化、上传结果未知、提交响应丢失和未完成准备均不会自动重发。
- 来源记录和提交回执保存在当前用户 APPDATA 的 `AIWork/seedance-references` 下；作用域包含网关及凭据的摘要标签。记录不保存 API Key 或提示词正文。不要删除未知任务的回执来强行重新生成。
- HTTP 错误保留允许公开的错误代码、HTTP 状态和经过格式验证的请求 ID，不输出原始上游错误正文、签名 URL、提示词或凭据。
