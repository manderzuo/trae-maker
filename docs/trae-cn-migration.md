# 统一 TRAE CN 迁移

TRAE CN 3.4 起合并旧 Work 与 IDE。本助手按安装包的产品信息识别客户端，旧 `TraeWork` 命令仍兼容；旧配置路径失效时识别统一版，有效的旧版自定义路径仍可保留。设置中的「TRAE CN 安装路径」填写 `Trae CN.exe`。

新原生授权使用安装包的 TRAE OAuth client_id，PKCE 请求与 AuthCode 交换绑定同一 client_id。账号中的 `oauth_client_id` 随导入、导出和凭据保存保留。未知来源的存量 refresh token 继续走旧版兼容客户端；不能因目录被迁移就改写来源。若续期失败，通过「添加账号 → 原生授权」重新登录即可更新来源和凭据。

3.4.2 的原生续期使用 P-256/SHA-256 设备签名，签名绑定请求方法、路径、ClientID、refresh token、时间和 nonce。助手的授权公钥、续期私钥与客户端快照保持同一对；私钥以当前 Windows 用户的 DPAPI 密文保存，原生快照使用客户端的 tc 加密容器。代理只在验证账号归属并保存完整凭据后记录请求已证明的设备上下文。签名材料缺失时保留旧凭据并提示重新授权，不用新随机密钥冒充原签名设备。

账号导出包含加密的设备绑定，同一 Windows 用户可随账号导入到其他助手目录。DPAPI 材料不能直接搬到另一台机器或另一 Windows 用户；那种情况下需要在目标环境重新授权。每日签到在已签、冷却和范围规则内先续期可刷新账号，再应用过期筛选。

统一版使用 `data/profiles_trae`。启动助手时只把 `data/profiles` 中有效且缺失的账号槽复制过去，不覆盖已存在的新槽，旧槽原地保留。`last`、`.bak` 和隐藏临时目录不作为账号槽展示。保存当前登录态要求目标 UID 与客户端实际 tc 登录容器一致。

账号发现、本地 JWT 捕获、手动与自动切换、项目列表、实例 EXE、代理和签到请求身份均使用解析后的客户端。原生 JWT 在内存中解密；列表保持掩码。项目接力只连接属于当前默认客户端实例的回环 CDP；端口由其他程序或隔离实例持有时明确拒绝。

双客户端并存时，显式选择的目标贯穿快照、续期和接力；有效旧自定义路径继续有效。非默认盘安装保留注册表和运行进程探测。默认实例关闭按 EXE、用户目录和进程树判断，不按所有同名进程关闭；独立实例保留。保存、切换和重开项目沿用受控的 CDP 与代理参数；CDP 选择原生会话页面，跳过新版悬浮按钮页面。

网关外部 API 与业务 function 保持。`solo_work_lite` 是协议值，继续保留。新版本的身份参数不能代替真实能力证据；视频续接的旧版本证据不自动沿用，计费、预算与 unknown 恢复守卫仍生效。

本地交付保留原 EXE、Python 和 PowerShell 资源，并备份原生核心登录文件。回滚运行资源不会删除新旧快照；无需回退或改写账号库。新建账号、交互式 OAuth 和付费生成的真实验证程度单独记录。

本次交付的检查结果、运行文件、回滚位置与未实测范围见 [2026-10-12 验证记录](trae-cn-migration-validation-2026-10-12.md)。
