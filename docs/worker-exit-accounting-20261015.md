# 未知执行退出和独立核账

schema 11 新增 `bridge_budget_worker_exits`，保存 budget 对应的本地退出世代与首次观察时间。它不表示上游取消、生成失败、成片交付或零收费。

退出记录仅由发送工作函数返回后的 guard，或取得独占租约后针对旧世代的维护流程生成。运行中的执行不能写退出记录，重复记录保留首次时间。普通状态查询、浏览器断开和用户请求字段均不能产生此证据。

原执行超过30分钟、退出观察超过60秒后，内部 execution 回执可携带 `worker_exit`，供 Core 独立回收父请求并发。文字步骤可以没有视频 task ID。原请求、预算与会话继续用于查询、防重和账单核对，不重新派发付费请求。

未知执行缺少终态时间时，核账使用退出时间加60秒作为独立时间点。必须取得该时间点之后、10分钟内、查询完整且 request/Key/account/session 精确一致的正数费用记录，才能生成 `post-worker-exit-session-observation-v1` 本地核验回执。此策略不是上游存在不可变 Final 标志的承诺；后续金额变化仍产生冲突并隔离，不覆盖首次扣费或重复扣款。零值候选与缺失账单保持待核，明确失败的未收费释放仍执行原有延迟及完整性验证。

发布前先对只读生产快照演练 schema 10 到11迁移，并验证原有财务、执行及身份记录不变。上线前必须全局静止并备份；旧二进制不支持11版账库。已有新账务后不得通过恢复旧库回滚。
