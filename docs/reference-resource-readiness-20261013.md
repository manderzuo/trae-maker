# 参考素材下载预检与失败反馈

这是本地防护补丁，**没有延长上游签名有效期，也没有证明原任务因排队导致链接过期**。

原任务得到上游明确的 `resource download failed`，耗时约 608 秒。原生资源只读查询返回的公开图片签名剩余约 600 秒；原图片仍能下载、摘要一致且完整解码通过。原提交时的签名和上游下载时间未保存，故不能排除上游下载超时等原因。

安装的 TRAE CN 3.4.2 客户端协议中，`get_resource_url` 仅有 `uri_list/inner/biz_type/scale/Request`，视频提交没有签名期限或刷新参数。`inner=true` 返回内部地址；本补丁不使用它，不向视频提交混入未经验证的公网 URL，也不添加臆造的期限字段。视频适配器仍为 0.1.50 / 20260811。

## 改动

- 原生上传计划与提交回执检查逻辑错误码，HTTP 200 不再等同于逻辑成功。
- 视频准备完成上传后，用绑定账号解析原生参考 ID，验证公开 CDN 可返回正确媒体类型及文件前缀。图片与视频均覆盖；无参考素材不增加请求。
- 所有素材预检共用 20 秒观察时限，解析响应最多 256 KiB，每份媒体读取 32 字节。最多四个探测线程；SDK DNS 卡住时观察会结束，线程继续占用槽位，不能进入视频生成。
- 解析和 CDN 请求均禁止重定向；CDN 不携带账号认证，拒绝私网、回环和混合 DNS 地址、带用户信息/非标准端口的 URL，以及已过期或剩余不足 30 秒的明确签名。
- `reference_resource_unavailable` 在视频提交前终止本次流程。Core 结束执行占用，已执行辅助步骤的费用仍按真实回执核对，后台不能随后继续生成。
- 上游已经提交后的资源下载失败使用 `reference_resource_download_failed`；保持执行失败与财务核对独立，不自动重新生成。
- Studio 本地和云端保留具体原因；账务查询不覆盖原因。同步 HTTP 400 的预检拒绝保存为明确失败；恢复响应日志不推断不存在的视频任务 ID、不虚构查询接口或重复 POST。

## 验证

观察到原逻辑错误上传响应、Core 未终止执行、Studio 同步拒绝被误报未知等回归先失败再通过。AI Work 7 项素材预检回归、Core 85 项反馈/准入/重连回归、Studio 101 项客户端回归及 18 项隔离 PostgreSQL 云端任务回归通过；TypeScript 类型检查和改动范围 lint 通过。Windows AI Work 与 Linux Core使用已有离线依赖构建。

原失败任务和成功对照任务的素材各通过一次实际生产预检代码的只读调用。凭据文件字节未变，新增视频生成调用为零。

## 限制

预检证明的是**提交前**可读取，文件前缀检查不是完整解码。生成服务随后自行创建的签名及其过期时刻仍由上游控制。上游排队超过签名期限时，需要上游延长有效期、开始执行前刷新签名，或正式支持长有效期的自有资源地址；本补丁不能保证这种上游故障不再发生。

原失败、未知任务及 P/R/D、回执、预留、原请求身份全部保留。不能从资源下载失败推出零扣费或退款。
